# PRD: Simple Todo (개인용 할일 관리 앱)

- 문서 버전: v1.0
- 작성일: 2026-09-03
- 작성자: (개인 프로젝트)
- 상태: Draft

## 1. 개요

### 1.1 배경
매일 10~20개 정도의 할일을 관리하는데, 기존에 쓰던 도구는 너무 무겁거나(캘린더/알람/공휴일 등 불필요한 기능) 반대로 너무 가벼워서(메모장, 종이) 카테고리 구분이나 진행률 파악이 안 됨. 딱 필요한 4가지 기능만 담은 가벼운 개인용 웹 앱이 필요.

### 1.2 목표
- 하루 단위로 할일을 빠르게 추가/관리할 수 있는 최소 기능 제품(MVP)
- 브라우저만 있으면 설치 없이 바로 사용, 새로고침해도 데이터 유지
- 업무/개인/공부 카테고리별로 오늘 얼마나 했는지 한눈에 파악

### 1.3 비목표 (이번 버전에서 하지 않는 것)
- 회원가입/로그인, 다중 사용자, 클라우드 동기화
- 모바일 네이티브 앱, PWA, 푸시 알림/알람
- 캘린더 뷰, 반복 일정, 마감일/우선순위 정렬 (향후 확장 후보로만 기록)
- 여러 기기 간 데이터 동기화 (같은 브라우저 내 저장이 전제)

## 2. 대상 사용자
- 본인 1인 사용 (개인용 프로젝트)
- 하루 10~20개 수준의 할일을 텍스트로 빠르게 기록하고 체크하는 사용 패턴

## 3. 핵심 기능

### 3.1 할일 추가 / 수정 / 삭제
- 입력창 + 추가 버튼(또는 Enter)으로 새 할일 생성
- 할일 텍스트는 인라인 편집(더블클릭 또는 편집 아이콘) 가능
- 삭제 시 즉시 삭제 (개인용 도구이므로 되돌리기/휴지통 없음, 삭제 전 간단한 확인만)
- 빈 문자열 등록 방지 (trim 후 빈 값이면 추가 안 함)

### 3.2 완료 체크
- 각 할일 항목에 체크박스 제공, 클릭 시 완료/미완료 토글
- 완료된 항목은 취소선 + 흐리게 표시로 시각적으로 구분
- 완료 항목은 목록 하단으로 이동하거나 별도 섹션으로 분리 (구현 시 택1, 기본은 하단 정렬 권장)

### 3.3 카테고리 분류
- 카테고리 3종 고정: 업무 / 개인 / 공부
- 할일 추가 시 카테고리 선택(기본값: 업무), 이후 수정 가능
- 카테고리별 색상 태그로 구분
- 카테고리 필터(전체/업무/개인/공부)로 목록 좁혀보기

### 3.4 진행률 보기
- 전체 진행률: 완료 개수 / 전체 개수 (%) 를 프로그레스 바 + 텍스트로 상단에 표시
- 카테고리별 진행률도 함께 표시 (예: 업무 2/5, 개인 1/3, 공부 3/4)
- 할일이 0개일 때는 진행률 0% 또는 "할일 없음" 상태로 표시

## 4. 데이터 & 저장

### 4.1 데이터 모델
```js
// Todo 객체 형태 (타입 강제는 없음, 순수 JS)
{
  id: '',          // string, crypto.randomUUID()
  title: '',       // string, 할일 내용
  category: '',    // 'work' | 'personal' | 'study'
  completed: false,
  createdAt: '',    // string, ISO 8601
  updatedAt: '',    // string, ISO 8601
}
```

### 4.2 저장 방식
- **브라우저 `localStorage`에 저장** (백엔드/DB 서버 불필요)
  - 이유: 1인 사용자, 단일 브라우저 사용 전제 → 새로고침/재접속 시에도 데이터가 남아야 한다는 요구사항을 서버 없이 가장 단순하게 충족
  - 앱 로드 시 localStorage에서 읽어 초기 상태 구성, 변경(추가/수정/삭제/완료토글) 시마다 즉시 저장
- 저장 키 예시: `simple-todo:v1`
- 데이터 손상/파싱 실패 시 빈 목록으로 안전하게 폴백 (앱이 죽지 않도록)

## 5. 기술 스택 (순수 JavaScript)

| 영역 | 선택 | 비고 |
|---|---|---|
| 마크업/스타일 | HTML5 + CSS3 | 프레임워크·전처리기 없음 |
| 로직 | 순수 JavaScript (ES 모듈) | 빌드 도구·트랜스파일 없이 브라우저가 직접 실행 |
| 모듈 구조 | `<script type="module">` + `import`/`export` | `js/storage.js`(저장) · `js/todos.js`(상태/CRUD) · `js/app.js`(진입점, DOM 렌더링) |
| 상태 저장 | 브라우저 `localStorage` | 서버/DB 없음 |
| 로컬 실행 | 정적 파일 서버 (예: `npx serve`) | 빌드 단계 아님 — ES 모듈 import가 `file://`에서 막히는 브라우저 제약을 피하기 위한 구동 방식일 뿐 |
| 백엔드 서버 | 없음 (MVP 범위 밖) | 정적 파일만으로 동작, 필요 시 아무 정적 호스팅에 그대로 배포 |

> 핵심 설계 결정: 이 앱은 **빌드 단계가 없는 순수 프론트엔드**입니다. React/Vite/TypeScript 같은 프레임워크·빌드 도구를 쓰지 않고 `index.html` + `css/` + `js/`만으로 구성해, "브라우저에서 바로 실행 + 새로고침해도 안 사라짐" 요구사항을 가장 단순하게 만족합니다. 로컬에서 열 때 정적 서버가 필요한 이유는 ES 모듈(`import`/`export`)이 보안 정책상 `file://`로 직접 열면 동작하지 않기 때문이며, Node.js는 그 정적 서버를 실행하는 용도로만 쓰인다.

## 7. 비기능 요구사항
- 최신 Chrome/Edge 기준 정상 동작 (개인 사용 브라우저 1종 기준, 폭넓은 크로스브라우저 대응은 비목표)
- 할일 20개 수준에서 추가/삭제/토글이 체감 지연 없이(100ms 이내) 반영
- 새로고침, 브라우저 재시작 후에도 데이터 유지 (localStorage 특성상 브라우저 캐시 삭제 시에는 소실될 수 있음을 인지하고 사용)

## 8. 성공 기준 (개인 프로젝트 기준)
- 하루 할일을 이 앱 하나로 추가·체크·분류까지 끝낼 수 있다
- 새로고침/재부팅 후에도 오늘 기록이 그대로 남아있다
- 진행률을 보고 오늘 얼마나 했는지 3초 안에 파악할 수 있다
